# 可进入生产的 Laya 决策场景与数据

核对日期：2026-09-21。本轮完成来源与任务筛选，没有下载新训练数据、训练模型或调用收费 LLM。以下优先级是基于任务形态、数据可得性和部署成本的工程判断，不是已经实测超过 LLM 的结论。

## 推荐选择

第一候选是商品搜索相关性：判断查询与商品是否准确匹配、可替代、互补或无关。第二候选是固定业务分类的客服分流。中文产品可优先验证检索结果重排，但当前测速使用的是英语 Laya，中文模型适配需要单独验证。

这些任务具有重复调用、有限输出和可收集业务标签的特点。领域数据可能帮助模型学习企业自己的判定口径；一次前向输出类别也有减少生成开销的潜力。两点都不能保证准确率超过指定的通用 LLM。BANKING77 上已有 GPT-3.5/GPT-4 在少样本设置中优于所比较微调分类器的反例：[2023 研究](https://aclanthology.org/2023.finnlp-1.7/)。该历史比较也不能直接代表今天的模型。

## 1. 商品搜索相关性、错配过滤与替代品识别

输入为搜索词与候选商品的标题、属性、描述；输出 ESCI 四分类及各类分数。例：搜索“iPhone 15 手机壳”，需要区分兼容保护壳、手机本体和不兼容型号。可部署在召回后的候选过滤及重排阶段，效果最终由搜索质量和业务实验衡量。

- [Amazon ESCI 官方](https://github.com/amazon-science/esci-data)：真实购物查询与人工相关性判断，大版约 262 万对，覆盖英语、西语和日语；四类为 Exact、Substitute、Complement、Irrelevant。发布许可 Apache-2.0。优先使用官方版本和 query 分组划分；[HF 转换版](https://huggingface.co/datasets/tasksource/esci)不能与官方版本混用统计口径。
- [WANDS 官方](https://github.com/wayfair/WANDS)：480 个查询、42,994 件候选商品、233,448 个相关性判断；MIT。查询来自历史客户行为日志，人工标注过程见 [Wayfair 说明](https://www.aboutwayfair.com/careers/tech-blog/wayfair-releases-wands-the-largest-and-richest-publicly-available-dataset-for-e-commerce-product-search-relevance)。23 万对不等于 23 万种独立查询。其标签体系与 ESCI 不完全相同，应事先定义映射，或独立训练评测。

价值判断：一条搜索请求通常涉及多条候选，适合批量分类。实际吞吐取决于候选数及商品长度，不能照搬单条短客服的测速数字。与 LLM 的比较应固定候选集合、输入字段和排名收益定义。分类看 Macro-F1、误杀相关商品比例；排名看 nDCG@10，同时报告召回阶段遗漏。最终用线上实验确认转化等业务指标。

生产依据：京东已发表相关性模型的线上部署与 A/B 测试工作，说明任务有实际落地点；它不能证明 Laya 优于今天的 LLM，也不要求我们复制其蒸馏数据来源。[产业论文](https://aclanthology.org/2022.emnlp-industry.5/)

## 2. 客服意图识别与工单分流

输入为客户问题或会话，输出固定意图、所属队列以及是否需要复核。可先做重复扣款、退款未到账、卡片未到等明确类别。小模型优势的候选来源是稳定的类别定义、较低处理成本和可独立校准的分流阈值；不能把模型最大概率直接当成实际正确率。

- [BANKING77](https://huggingface.co/datasets/PolyAI/banking77)：10,003 条训练、3,080 条测试，77 种英文银行客服意图，CC BY 4.0。来源卡片称在线银行查询，但初始采集细节不完整。它不覆盖所有电商、软件客服或长会话问题。旧 HF 加载脚本不兼容新 datasets，可用 [官方 CSV](https://github.com/PolyAI-LDN/task-specific-datasets/tree/master/banking_data)或固定版本的 [Parquet 镜像](https://huggingface.co/datasets/legacy-datasets/banking77)。
- [CLINC150/OOS](https://github.com/clinc/oos-eval)：150 个已知意图，含范围外问题，可补充拒绝强行分类的评测。它是众包构造、单意图数据，不应称为真实生产工单或拿来替代本业务的异常样本。

生产评测：Macro-F1、逐类召回、达到约定正确率时能自动处理的比例，以及剩余请求转人工或 LLM 的总成本。固定类别还必须比较 TF-IDF/线性分类器和直接分类头，不能预设 Laya 决策头最优。多意图和跨消息状态变化需业务新增标签。

### BANKING77 与当前 Laya 输入实现的实际兼容检查

2026-09-21 只读取官方 `categories.json`，使用本地 Laya 分词器、全部 77 个原始类别名称和一条自拟客服文本检查预处理，未训练或运行模型推理。默认 `head_max_len=192` 会截短 64 个候选，77 个类别只剩 67 种不同的候选 token 序列；例如丢卡和丢手机的类别文字会被裁成相同前缀。即使 `max_len=8192`，这一独立的候选预算限制仍然存在。

该测试中按完整候选长度计算出 `head_max_len=585` 后，77 个候选均保留完整，共 582 个输入 token。此数值仅对应本次无额外类别说明的格式及示例，正式预处理应按实际问题与类别描述计算预算，断言候选和目标一一对应，不能把 585 当成所有格式的固定要求。结果记录见 [输入检查](../results/banking77-input-fit.json)。BANKING77 提供的是意图标签，生产中的意图到服务队列映射仍需业务定义。

## 3. 中文知识库检索与 RAG 候选重排

输入为用户问题和候选段落，输出相关性等级。可以作为企业搜索和 RAG 中的重排组件；相关性标签不等价于“答案受证据支持”或“文档已获授权”，不可用这个分类器代替答案核验或权限控制。

[T2Ranking](https://huggingface.co/datasets/THUIR/T2Ranking)提供来自搜狗真实查询日志的中文问题及专家四级相关性标注：258,042 个训练查询、1,613,421 条训练判断、2,303,643 个段落，Apache-2.0。两亿条检索负例不等于两亿条人工标注。使用训练 qrels 导入，保留开发/测试边界，不将 C-MTEB 测试集混入训练。

价值判断：每次只判断有限候选的相关性，任务清楚，适合批量评分；但成熟的专用 reranker 是必须比较的基线。采用检索指标和下游回答质量双重评测。当前英语 Laya 不能因可分词就被视为已具备中文生产能力。

## 4. 多商家商品匹配、目录去重与比价

输入为两条商品记录，输出是否指同一商品，可降低目录重复与跨商家比价的人工成本。需区分同系列、不同容量、套装和单品；先用可信商品标识及规格规则处理确定情况，再对剩余候选做模型判断。相同型号的具体定义应由业务固定。

[WDC Products](https://webdatacommons.org/largescaleproductcorpus/wdc-products/)来自真实电商网页，含 11,715 条商品报价、2,162 个商品实体，提供不同难度及未见商品比例的划分。标签主要依靠商品标识聚类，人工抽查估计约 4% 噪声，不能当作全部人工金标。较早版本也有 [HF 数据](https://huggingface.co/datasets/wdc/products-2017)，训练标签为弱监督、测试人工检查；其数据卡许可显示 unknown，因此暂不列入首批生产训练材料，不能拿工具代码许可证代替数据许可。

生产指标优先关注自动合并精确率、该精确率下的召回及复核量；候选召回单独测量。商品匹配已在真实大规模商品集上有产业研究，但这些研究并未验证本项目的 Laya。[产业论文](https://aclanthology.org/2023.emnlp-industry.22/)

## 5. 长投诉正文分类与运营归档

输入为完整投诉正文，输出产品、问题或运营队列。相较短意图任务，这一方向更值得测试 8k 预算，但需先统计实际长度；不能假定每条投诉都很长。

[CFPB 官方历史正文归档](https://www.consumerfinance.gov/foia-requests/foia-electronic-reading-room/cfpb-consumer-complaint-database-narratives-archive/)覆盖曾公开的历史投诉，最晚到 2026-08-14。字段语义见 [官方说明](https://www.consumerfinance.gov/complaint/data-use/)：product/issue 是消费者选择的分类，不能当成责任认定。正文已从在线数据库移除，当前主库不能作为持续新增正文源；这一变化由 [2026 年 9 月发布说明](https://cfpb.github.io/api/ccdb/release-notes.html)确认。

导入时按时间切分、统一分类口径、保留非空正文；公司回复、目标类别和事后处理结果不能放进输入。最终还需本业务工单标签和近期材料验证迁移效果。

## 备选：社区评论审核初筛

[Civil Comments](https://huggingface.co/datasets/google/civil_comments)含 1,804,874 条训练、97,320 条验证、97,320 条测试，来自 2015–2017 年真实英文新闻站点评论，CC0。可做固定政策下的多标签初筛，但语料较旧、人工评分存在分歧，应保留标签比例，并补充当下平台样本；不是中文、多模态或所有审核政策的直接替代。

## 如何证明比 LLM 做得好

两种结果分开报告：任务质量超过某个固定版本的 LLM；或质量接近但服务成本、吞吐更好。不能用后一种冒充前一种。当前两者都没有在这些数据上由本项目证实。

1. 选择一个业务任务，固定标签口径、模型版本、输入字段和 LLM 提示；给 LLM 合理的类别说明和只来自训练/开发集的示例，支持结构化输出，避免故意设弱基线。
2. 比较原始 Laya、微调 Laya、任务专用基线和指定 LLM；若目标只是固定分类，允许更简单模型胜出。
3. 按查询、会话、商品实体或时间划分。公开集结果与从未用于调参的本业务集结果分开，所有衍生样本归同组。阈值和校准只在开发/校准集选择。
4. 按组估计质量差异及置信区间；比较相同流量、输入长度和目标负载下的端到端 P50/P95、吞吐、每万条成本。调用失败与兜底请求也计入。
5. 上线先做影子评测，再做可回滚的小流量实验；判错成本与可自动处理比例一起报告。搜索还要看业务效果，路由还要看人工改派率。

8k 保留为上限，不要求把短数据填长。已完成的合成 8k 训练测速只证明计算链路可运行，不证明这些任务的推理速度或生产质量。

## 第一轮建议

若先验证英语 Laya，优先选 ESCI 英语任务，先从官方训练部分按查询成组取有限子集开展基线，保留官方测试；WANDS 用于独立的家居领域实验，不能未经标签映射就混合。若目标是中文知识库，则改以 T2Ranking 和合适的中文/多语言模型为起点。先分别验证单任务，达到目标后再评估多任务混合，避免混训后无法定位收益和退化。
