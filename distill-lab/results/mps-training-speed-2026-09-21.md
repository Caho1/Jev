# Laya 本机 MPS 训练测速 · 2026-09-21

M5 Pro 48 GiB 上，Laya 的 LoRA 加决策头微调与全量分类微调均通过真实前向、反向和 AdamW 更新。四组测试各预热 5 步、计时 30 步，测试结束后没有保存微调权重，原始模型缓存保持作为每次运行的起点。

## 条件

- 硬件：Apple M5 Pro，48 GiB 统一内存；macOS 27.0。
- 软件：PyTorch 2.14.0、Transformers 4.57.6、PEFT 0.21.0、safetensors 0.8.0；依赖由 `../uv.lock` 固定。
- 模型：`convaiinnovations/laya`，检查点 `1c5edc17a7acd8701df6fc341c0d179f1c62c982`，421,293,827 个原始参数，严格匹配全部权重键。
- 执行：MPS、FP32、SDPA、batch 4，不使用梯度检查点、梯度累积或 CPU 算子回退。每个计时阶段使用 MPS 同步。
- 损失：四分类交叉熵。全量模式训练编码器和决策头共 421,029,889 个参数，动作头不参与损失和更新，但保留原有前向计算。
- LoRA：编码器每层注意力的 `Wqkv`、`Wo`，rank 16、alpha 32、dropout 0；同时训练完整决策头，共 30,635,009 个可训练参数。
- AdamW：weight decay 0.01、foreach=False。全量编码器学习率 2.5e-5；LoRA 和决策头学习率 1e-4。随机种子 42。
- 输入：四条合成客服文本，重复以填满指定 token 长度，无 padding；样本与标签在设备上预先准备。每次独立进程重新加载同一初始检查点。

## 实测结果

| 模式 | Token 数 | 平均秒/步 | 标准差（秒） | 条/秒 | MPS 驱动内存采样最大值（GiB） |
|---|---:|---:|---:|---:|---:|
| [LoRA + 决策头](mps-lora-b4-l256.json) | 256 | 0.423 | 0.009 | 9.46 | 5.22 |
| [LoRA + 决策头](mps-lora-b4-l512.json) | 512 | 0.913 | 0.032 | 4.38 | 9.37 |
| [全量分类微调](mps-full-b4-l256.json) | 256 | 0.599 | 0.014 | 6.68 | 9.07 |
| [全量分类微调](mps-full-b4-l512.json) | 512 | 1.120 | 0.013 | 3.57 | 13.23 |

内存记录是初始化和每一步结束时采样的最大值，包含驱动与缓存，不能当作步内瞬时峰值；统一内存下也不应与进程 RSS 相加。原始 JSON 另含张量内存、RSS、每一步损失及耗时。

| 模式 | Token 数 | 前向（秒） | 反向（秒） | AdamW（秒） |
|---|---:|---:|---:|---:|
| LoRA + 决策头 | 256 | 0.179 | 0.224 | 0.020 |
| LoRA + 决策头 | 512 | 0.402 | 0.491 | 0.020 |
| 全量分类微调 | 256 | 0.166 | 0.308 | 0.125 |
| 全量分类微调 | 512 | 0.364 | 0.636 | 0.120 |

256 token 时 LoRA 吞吐约为全量的 1.42 倍；512 token 时约为 1.23 倍。LoRA 降低了可训练参数量和优化器开销，但仍需运行整个编码器并传递梯度。此处没有比较微调效果，也没有穷举最优 batch、精度或训练后端。

## 训练时间外推

按相同输入长度、batch 和短时吞吐，使用 `数据条数 ÷ 条/秒` 计算一轮纯训练时间：

| 模式 | Token 数 | 1 万条 / 1 轮 | 10 万条 / 1 轮 |
|---|---:|---:|---:|
| LoRA + 决策头 | 256 | 17.6 分钟 | 2.94 小时 |
| LoRA + 决策头 | 512 | 38.0 分钟 | 6.34 小时 |
| 全量分类微调 | 256 | 25.0 分钟 | 4.16 小时 |
| 全量分类微调 | 512 | 46.7 分钟 | 7.78 小时 |

以上仅是外推，不包含数据读取、分词、设备传输、验证、保存与校准，也不保证长时间训练下的温度、功耗和速度稳定性。一条业务记录若拆成多道问题，应按实际训练样本数估算。

## 验证与边界

所有模型参数与输入位于 MPS，禁用了不支持算子的 CPU 回退。每组首个预热步均检查编码器参数（全量权重或 LoRA B）和评分头参数的梯度为有限非零值，并确认 AdamW 确实改变权重。全部迭代的损失均为有限值。

固定的小批次很容易拟合，后续损失接近零；这里测量的是同形状的完整计算过程。损失下降不能用于证明业务准确率、泛化或真实数据收敛。正式训练集、验证集与测试集尚未准备，本轮没有进行正式业务训练。

## 复现

在 `distill-lab` 目录、VS Code 终端中执行：

```sh
uv sync --extra training
uv run --extra training python scripts/benchmark_mps_training.py \
  --mode lora --batch-size 4 --seq-len 256 --warmup 5 --steps 30 \
  --output results/mps-lora-b4-l256.json
```

将 `--mode` 改为 `full`、`--seq-len` 改为 `512` 可复现其余组合，输出文件名相应修改。脚本默认只读取本机已有缓存；其他机器需先准备同一检查点，或通过 `--weights` 指定本地目录。

测速代码见 [benchmark_mps_training.py](../scripts/benchmark_mps_training.py)。上游模型代码固定为 Laya commit `42626c348753fbb17572a813127df2278a1ec527`，来源、SHA256 与许可证保存在 `../reference/`。
