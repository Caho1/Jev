# jev-ultrafast 接入本地 Laya：第一轮诊断

2026-09-22，本机 MPS / FP32。已接入 TypeSafe 兼容本地接口，完成同一批冻结输入上的两模型对照，以及真实 Chrome DOM 的闭环执行。**接口可用，但目前模型效果不足以承担可靠的浏览器自动化。**

| 指标 | 原始 Laya | Computer Use 微调版 |
|---|---:|---:|
| 操作类型准确率 | 16/48，33.33% | 18/48，37.50% |
| 给定正确操作后的目标准确率 | 12/28，42.86% | 9/28，32.14% |
| 整步准确率：操作与目标均正确 | 8/48，16.67% | 9/48，18.75% |
| 中文目标的整步准确率 | 4/24，16.67% | 4/24，16.67% |
| 英文目标的整步准确率 | 4/24，16.67% | 5/24，20.83% |
| 闭环：实际到达目标页面状态 | 4/8 | 4/8 |
| 闭环：到达目标状态且正确报告 DONE | 4/8 | 2/8 |
| 单步 HTTP 请求耗时中位数 | 385 ms | 452 ms |
| 单步 HTTP 请求耗时 P95 | 654 ms | 554 ms |
| 合法响应 | 48/48 | 48/48 |

目标准确率是读取标准操作所对应的目标头，不代表模型实际执行正确；整步准确率才同时要求操作与目标正确。28 个目标题都不止一个候选。终态题只要求操作正确。闭环的实际终态和模型是否正确停止分别报告，不能把模型声称 DONE 当成成功。

## 本次测了什么

- 24 个手写本地 HTML 场景，每个配中、英文目标，共 48 步。页面控件文字均为英文；这是目标语言对照，不是完整中文网页测试。两种语言共享场景，不是 48 个独立任务。
- 12 步点击、8 步填文本、8 步选择下拉项、8 步 DONE、4 步 WAIT、4 步 BLOCKED、2 步向下滚动、2 步向上滚动。通过 Chrome 执行原始 `snapshot.js`，先冻结全部页面，再运行两套固定权重。
- 4 个闭环任务，各配中英文目标，共 8 个：打开文章、设置并保存复选框、设置并应用货币、两级页面导航。每个最多 10 次决策；使用模型自己产生的历史，没有提供下一步答案。
- 保留 ultrafast 原始 Agent 循环、动作索引、页面新鲜度与遮挡检查、执行后记录顺序。测试仅用 Playwright 将浏览器协议传输接到隔离的无头 Chrome；不连接个人浏览器资料。
- 所有闭环验收条件在推理前已用真实浏览器操作检查：初始状态为失败，正确操作后为成功。正式闭环通过独立 DOM 表达式验收。
- 此次闭环没有需要生成填写内容的任务。离线 TYPE_TEXT 只评估操作与字段选择，没有评估文字生成。完整表单自动化仍需单独配置 text helper。

这是小型合成场景诊断，不是公开网页基准或生产准确率。未读取校准/留出集，未训练、未调参，未调用付费模型 API。没有重新评估历史 BANKING77 或 Mind2Web 的准确率。

## 错误集中在哪里

原始 Laya 在全部 8 个 TYPE_TEXT 和全部 8 个 SELECT 步骤上都选择了 CLICK；微调版在这两类操作上也没有命中。两者在 8 个 DONE 和 4 个 WAIT 冻结步骤上均未命中正确操作。有效的 JSON 和观察范围内的合法控件，不能保证动作语义正确。

闭环中，原始模型在复选框任务中反复切换或过早提交；货币设置任务直接误报完成。微调模型能够打开文章，但在两个语言版本中随后误报 BLOCKED，所以两者实际到达终态均为 4/8，严格成功数分别为 4/8 与 2/8。

现有 Computer Use 检查点训练的是“某控件是否是下一步目标”的二分类任务，未针对 ultrafast 的八类操作和各操作目标 Choice 题训练。这是任务格式不一致的事实；不能仅凭本轮结果断言它是全部错误的原因。当前结果不支持直接用该微调版替换浏览器决策模型。

## 接入改动

ultrafast 的 `model.py` 新增 `TYPESAFE_BASE_URL`，默认云端行为保持兼容；loopback 请求不发送云端密钥。适配器在 `../../scripts/ultrafast_laya.py`，复用已有经过权重校验的本地加载器。

适配器将结构化 instructions 转成 JSON 文本、保留完整候选描述；唯一候选直接返回并单独标记；多候选输入超过 8,192 tokens 时拒绝，不截断。原来的“只消费所选操作对应的目标头”校验继续生效。

本地一次 HTTP 请求包含所有目标头，但每个非单候选题分别做一次前向，没有共享编码或 KV 缓存。两模型在 48 步回放中各执行 88 次前向、18 个单候选头直接解析；输入最长 671 tokens，因此这里的速度不能外推到 8K 页面。

权重分别为原始基础模型加训练前初始状态，以及固定的 Computer Use epoch-1。完整 SHA-256、设备、校准状态见各模型 `identity.json`。没有加载 BANKING77 客服微调 adapter。

## 复跑与当前服务

当前已启动原始 Laya 服务 `http://127.0.0.1:8767`，以及指向它的 [ultrafast 检查界面](http://127.0.0.1:8766)。健康检查和检查界面的状态接口均返回 200。检查界面空闲，尚未启动它的在线网页任务；正常界面的浏览器仍需 Browser Harness 连接，填写文本仍需生成模型。

在 `distill-lab` 目录执行，使用现有训练环境：

```bash
uv pip install --python .venv/bin/python -r requirements-ultrafast-local.txt
.venv/bin/python scripts/ultrafast_laya.py --variant laya_base --device mps
```

在另一个终端、`reference/jev-ultrafast` 目录启动检查界面：

```bash
TYPESAFE_BASE_URL=http://127.0.0.1:8767/v1 TYPESAFE_MODEL=laya_base uv run jev
```

如果当前端口已在运行，不必重复启动。换模型时重启本地服务并指定 `--variant laya_computer`。

独立重跑本轮测试，输出目录必须不存在：

```bash
.venv/bin/python scripts/evaluate_ultrafast_local.py --output results/ultrafast-local-new
```
